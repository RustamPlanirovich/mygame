Технический Стек Проекта "Protocol Yggdrasil"

1. Ядро (Core)

Мы используем TypeScript как основной язык.

Язык: TypeScript 5.x

Зачем: В игре будет более 50 типов ресурсов, сотни зданий и сложная логика крафта. Без строгой типизации (Strict Mode) мы утонем в багах "undefined is not an object". Нам нужны Интерфейсы для всего: Resource, Building, Ship.

Сборщик: Vite

Зачем: Мгновенный запуск сервера, горячая замена модулей (HMR), отличная оптимизация бандла. На порядок быстрее Webpack.

2. Фронтенд и UI (Interface)

Игра на 90% состоит из интерфейсов (таблицы, кнопки, прогресс-бары).

Фреймворк: React 18

Зачем: Компонентный подход идеален для игр. Мы создадим компонент <BuildingCard /> и переиспользуем его 100 раз. Экосистема React огромна.

Стилизация: Tailwind CSS

Зачем: Позволяет верстать сложные "киберпанк" интерфейсы прямо в HTML классах. Легко делать адаптив под мобилки.

Анимации UI: Framer Motion (для плавного появления окон, всплывающих тултипов и переходов меню).

Иконки: Lucide-React или Phosphor Icons (у них отличный техно-стиль).

3. Игровой Движок и Графика (Engine)

Для отрисовки космоса, частиц, турелей и тысяч врагов DOM (HTML теги) будет тормозить.

Рендеринг (Canvas): PixiJS (v7 или v8)

Зачем: Самый быстрый 2D WebGL рендерер. Он легко отрисует 10,000 частиц (энергия, выстрелы) при 60 FPS, не нагружая процессор так, как это делает HTML.

Связка с React: @pixi/react

Зачем: Позволяет управлять графикой PixiJS через React-компоненты.

4. Математика и Логика (Math)

Стандартные числа в JavaScript (number) ломаются после $1.8 \times 10^{308}$. В Idle играх числа уходят в $10^{5000+}$.

Библиотека Чисел: break_eternity.js (или Decimal.js)

Зачем: Стандарт индустрии для игр типа Antimatter Dimensions. Позволяет работать с числами вплоть до $10^{10^{308}}$. Очень быстрая и оптимизированная.

Форматирование: format-number (кастомная утилита)

Зачем: Чтобы выводить "1.52e12" или "1.52T" вместо "15235235235235".

5. Управление Состоянием (State Management)

Сердце игры. Нужно хранить количество ресурсов, уровни зданий, открытые технологии.

Библиотека: Redux Toolkit (RTK) или Zustand

Рекомендация: Zustand.

Зачем: Он проще Redux, работает быстрее и создает меньше "бойлерплейта" (лишнего кода). Отлично подходит для игр, где состояние меняется 60 раз в секунду (Game Loop).

Паттерн: Game Loop внутри requestAnimationFrame.

Мы не обновляем React-стейт на каждый кадр (это убьет производительность). Мы обновляем "Ref-объект" (mutable store) для математики, а React обновляем раз в 100-500мс для визуализации цифр.

6. Сохранение и Бэкенд (Persistence)

Локально (MVP): localStorage + lz-string

Зачем: lz-string сжимает JSON сохранения, чтобы никто не мог просто отредактировать "money": 999999 в консоли (хотя бы защита от дурака) и чтобы экономить место.

Облако (Позже): Firebase (Auth + Firestore)

Зачем: Авторизация Google, облачные сохранения (играй с телефона и ПК), таблицы лидеров.

Итоговая Архитектура Проекта

/src
  /assets          # Картинки, звуки, шрифты
  /components      # UI Компоненты (Button, Modal, ResourceBar)
    /game          # Игровые виджеты (BuildingList, TechTree)
  /core            # Игровая логика (Чистая математика, без React)
    /constants     # Баланс (цены, множители)
    /loop          # Главный цикл (GameLoop.ts)
    /math          # Обертки над break_eternity
  /features        # Redux/Zustand слайсы
    /resources
    /buildings
    /research
  /hooks           # Кастомные хуки (useGameLoop, useAutosave)
  /utils           # Форматирование чисел, сжатие сохранений
  App.tsx
  main.tsx
