# Система множественных сохранений

## Обзор

Реализована система множественных сохранений с поддержкой:
- Создание и управление пользовательскими сохранениями
- Автоматические сохранения (хранятся последние 3)
- Загрузка любого сохранения
- Удаление сохранений

## Изменения в БД

### Обновленная структура таблицы `game_save`

```sql
CREATE TABLE game_save (
  id SERIAL PRIMARY KEY,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  save_type TEXT NOT NULL CHECK (save_type IN ('manual', 'auto')),
  data JSONB NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

**Ключевые изменения:**
- `id` изменен с TEXT на SERIAL (автоинкремент)
- Добавлено поле `name` - название сохранения
- Добавлено поле `save_type` - тип сохранения ('manual' или 'auto')
- Добавлено поле `created_at` - дата создания
- `user_id` теперь NOT NULL

### Индексы

- `idx_game_save_user_id` - быстрый поиск по пользователю
- `idx_game_save_type` - поиск по типу сохранения
- `idx_game_save_updated` - сортировка по дате обновления
- `idx_game_save_manual_name` - уникальность имени для ручных сохранений

## API Эндпоинты

### GET /api/saves
Получить список всех сохранений пользователя

**Headers:**
- `x-user-id` - ID пользователя

**Response:**
```json
{
  "ok": true,
  "saves": [
    {
      "id": 1,
      "name": "Мое сохранение",
      "save_type": "manual",
      "created_at": "2025-12-26T10:00:00Z",
      "updated_at": "2025-12-26T12:00:00Z"
    }
  ]
}
```

### GET /api/saves/:id
Получить конкретное сохранение со всеми данными

**Headers:**
- `x-user-id` - ID пользователя

**Response:**
```json
{
  "ok": true,
  "save": {
    "id": 1,
    "name": "Мое сохранение",
    "save_type": "manual",
    "data": { ... },
    "created_at": "2025-12-26T10:00:00Z",
    "updated_at": "2025-12-26T12:00:00Z"
  }
}
```

### GET /api/saves/latest/manual
Получить последнее ручное сохранение (для автозагрузки при входе)

**Headers:**
- `x-user-id` - ID пользователя

**Response:** То же, что GET /api/saves/:id

### PUT /api/saves
Создать новое или обновить существующее сохранение

**Headers:**
- `x-user-id` - ID пользователя
- `Content-Type: application/json`

**Body:**
```json
{
  "name": "Название сохранения",  // Обязательно для manual
  "saveType": "manual",           // 'manual' или 'auto'
  "data": { ... },                // Данные игры
  "saveId": 123                   // Опционально, для обновления существующего
}
```

**Особенности:**
- Для автосохранений имя генерируется автоматически
- Автоматически удаляются старые автосохранения (оставляет 3)
- Для ручных сохранений проверяется уникальность имени

**Response:**
```json
{
  "ok": true,
  "save": {
    "id": 1,
    "name": "Название сохранения",
    "save_type": "manual",
    "created_at": "2025-12-26T10:00:00Z",
    "updated_at": "2025-12-26T10:00:00Z"
  }
}
```

### DELETE /api/saves/:id
Удалить сохранение

**Headers:**
- `x-user-id` - ID пользователя

**Response:**
```json
{
  "ok": true
}
```

### Обновленное автосохранение

- `saveGame()` теперь создает автосохранение
- Автоматически поддерживаются только последние 3 автосохранения
- При входе загружается последнее ручное сохранение

## Использование

### 1. Создание нового сохранения

1. Нажмите кнопку "Сохранения" в верхней панели
2. Нажмите "Создать новое сохранение"
3. Введите название
4. Нажмите "Создать"

### 2. Загрузка сохранения

1. Откройте менеджер сохранений
2. Найдите нужное сохранение
3. Нажмите кнопку "Загрузить" (зеленая кнопка со стрелкой)
4. Страница перезагрузится с выбранным сохранением

### 3. Удаление сохранения

1. Откройте менеджер сохранений
2. Найдите ненужное сохранение
3. Нажмите кнопку "Удалить" (красная кнопка с корзиной)
4. Подтвердите удаление

### 4. Автосохранения

- Создаются автоматически каждые 30 секунд
- Хранятся последние 3
- Можно загрузить как и обычные сохранения
- Нельзя удалить вручную (удаляются автоматически)

## Миграция данных

### Применение миграции

```bash
# Способ 1: Использовать скрипт
chmod +x server/apply_migration.sh
./server/apply_migration.sh

# Способ 2: Напрямую через psql
psql $DATABASE_URL -f server/migration_multiple_saves.sql
```

⚠️ **ВНИМАНИЕ:** Миграция удалит все существующие сохранения!

### После миграции

1. Перезапустите API сервер: `npm run dev:api`
2. Перезагрузите страницу игры
3. Создайте первое сохранение

## Технические детали

### Хранение текущего сохранения

ID текущего активного сохранения хранится в `localStorage`:
```javascript
localStorage.setItem('currentSaveId', saveId.toString());
```

### Логика автосохранения

1. При автосохранении вызывается `saveGame()`
2. Если есть `currentSaveId` - обновляется существующее автосохранение
3. Если нет - создается новое
4. Старые автосохранения удаляются, остаются последние 3

### Логика загрузки при входе

1. При входе в игру запрашивается `GET /api/saves/latest/manual`
2. Если есть - загружается последнее ручное сохранение
3. Если нет - начинается новая игра
4. `currentSaveId` сохраняется в localStorage
